# 152. Maximum Product Subarray

> **Difficulty:** Medium  
> **Language:** Java  
> **Pattern:** Dynamic Programming (Kadane's Algorithm Variation)

## 🔗 Problem Link

# 📝 Problem Statement

Given an integer array `nums`, find the **contiguous subarray** that has the **largest product**, and return that product.

- A subarray must be contiguous.
- The answer is guaranteed to fit in a 32-bit integer.

### Example 1

```text
Input: nums = [2,3,-2,4]
Output: 6

Explanation:
The subarray [2,3] has the maximum product.
2 × 3 = 6
```

### Example 2

```text
Input: nums = [-2,0,-1]
Output: 0

Explanation:
[-2,-1] is not a contiguous subarray because 0 lies between them.
```

---

# 💡 Intuition

This problem looks similar to **Maximum Sum Subarray (Kadane's Algorithm)**, but multiplication behaves differently.

### Why can't we keep only the maximum product?

Because multiplying by a **negative number** changes everything.

Example:

```text
nums = [-2,3,-4]
```

If we only keep the maximum product,

```text
-2
-2 × 3 = -6
```

We lose track of `-6`.

Later,

```text
-6 × -4 = 24
```

which becomes the answer.

Therefore, besides the maximum product, we also need to remember the **minimum product**, because a negative × negative becomes positive.

---

# 🔍 Key Observation

At every index we calculate three possible products.

```
1. Current element itself
2. Current element × previous maximum product
3. Current element × previous minimum product
```

So,

```
maxEnding =
max(current,
    current × previousMax,
    current × previousMin)

minEnding =
min(current,
    current × previousMax,
    current × previousMin)
```

Finally,

```
answer = max(answer, maxEnding)
```

# 🧠 Variables Used

| Variable | Meaning |
|-----------|----------|
| `maxEnding` | Maximum product ending at current index |
| `minEnding` | Minimum product ending at current index |
| `curr` | Overall maximum product found so far |

# ⚠️ Why Do We Store Minimum Product?

Example

```text
nums = [-2,3,-4]
```

| Number | maxEnding | minEnding |
|---------|------------|------------|
| -2 | -2 | -2 |
| 3 | 3 | -6 |
| -4 | 24 | -12 |

Without storing `minEnding`, we would never get `24`.

---

# ✅ Algorithm

1. Initialize

```text
maxEnding = nums[0]
minEnding = nums[0]
answer = nums[0]
```

2. Traverse the array from index `1`.

3. Compute

```text
v1 = nums[i]
v2 = maxEnding * nums[i]
v3 = minEnding * nums[i]
```

4. Update

```text
maxEnding = max(v1, v2, v3)
minEnding = min(v1, v2, v3)
```

5. Update answer

```text
answer = max(answer, maxEnding)
```

6. Return answer.

---

# ✅ Java Solution

```java
class Solution {
    public int maxProduct(int[] nums) {

        int maxEnding = nums[0];
        int minEnding = nums[0];
        int curr = nums[0];

        for (int i = 1; i < nums.length; i++) {

            int v1 = nums[i];
            int v2 = maxEnding * nums[i];
            int v3 = minEnding * nums[i];

            maxEnding = Math.max(v1, Math.max(v2, v3));
            minEnding = Math.min(v1, Math.min(v2, v3));

            curr = Math.max(curr, maxEnding);
        }

        return curr;
    }
}
```

## 🎯 Key Takeaways

- Keep track of both maximum and minimum products.
- A negative number can turn the smallest product into the largest.
- Update the global answer after processing each element.
- This is a classic **Dynamic Programming / Kadane's Algorithm variation** with **O(n)** time and **O(1)** space.

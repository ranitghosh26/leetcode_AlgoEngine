# 1186. Maximum Subarray Sum with One Deletion

**LeetCode:** https://leetcode.com/problems/maximum-subarray-sum-with-one-deletion/

**Difficulty:** Medium

**Topics:** Dynamic Programming, Array

---

# Problem Statement

Given an integer array `arr`, return the **maximum sum** of a **non-empty contiguous subarray** where you are allowed to **delete at most one element**.

The subarray must remain **non-empty** after deletion.

---

## Examples

### Example 1

```text
Input: arr = [1,-2,0,3]

Output: 4

Explanation:
Choose subarray [1,-2,0,3]
Delete -2

Remaining subarray:
[1,0,3]

Sum = 4
```

---

### Example 2

```text
Input: arr = [1,-2,-2,3]

Output: 3

Explanation:
Choosing only [3] gives the maximum sum.
```

---

### Example 3

```text
Input: arr = [-1,-1,-1,-1]

Output: -1

Explanation:
The subarray cannot become empty after deletion.
```

---

# Intuition

This problem is an extension of **Kadane's Algorithm**.

Normally, Kadane only finds the maximum subarray sum **without deleting anything**.

Now we are allowed to delete **one element**, so for every position we need to know two situations:

1. We haven't deleted anything.
2. We have already deleted one element.

This leads to two DP states.

---

# DP States

## 1. keep[i]

Maximum subarray sum ending at index **i** without deleting any element.

Exactly the same as Kadane.

```
keep[i]
```

---

## 2. delete[i]

Maximum subarray sum ending at index **i** after deleting **exactly one** element.

```
delete[i]
```

---

# State Transition

## Case 1 : keep[]

We either

Start a new subarray

```
arr[i]
```

or

Extend previous subarray

```
keep[i-1] + arr[i]
```

Therefore

```java
keep[i] = Math.max(arr[i], keep[i-1] + arr[i]);
```

---

## Case 2 : delete[]

There are two possibilities.

### Option 1

Delete the current element.

If we delete `arr[i]`, then the answer becomes

```
keep[i-1]
```

because everything before i has no deletion.

Example

```
1 2 -100

Delete -100

Answer = 3
```

---

### Option 2

Deletion has already happened earlier.

Just extend the deleted subarray.

```
delete[i-1] + arr[i]
```

Therefore

```java
delete[i] = Math.max(
        keep[i-1],
        delete[i-1] + arr[i]
);
```

# Why delete[0] = 0?

```java
delete[0] = 0;
```

This does **NOT** mean the answer can become zero.

It only initializes the DP.

The final answer is initialized as

```java
ans = arr[0];
```

So for an array like

```
[-5]
```

the answer remains

```
-5
```

not

```
0
```

---

# Correctness Proof

We prove by induction.

## keep[i]

Assume `keep[i-1]` stores the maximum subarray ending at `i-1`.

A subarray ending at `i` has only two possibilities:

- Start at i
- Extend previous subarray

Hence

```
keep[i]
```

is correct.

---

## delete[i]

Assume `delete[i-1]` is correct.

A subarray ending at `i` with one deletion can only be formed by

- deleting current element
- deletion happened before

No other possibility exists.

Therefore

```
delete[i]
```

is correct.

Thus both DP arrays are correct.

---

# Complexity Analysis

### Time

```
O(n)
```

Single traversal.

---

### Space

```
O(n)
```

For two DP arrays.

---

# Space Optimization

Since every state only depends on the previous state, we can reduce the space to

```
O(1)
```

using four variables.

---

# Java Solution

```java
class Solution {
    public int maximumSum(int[] arr) {

        int n = arr.length;

        int[] keep = new int[n];
        int[] delete = new int[n];

        keep[0] = arr[0];
        delete[0] = 0;

        int ans = arr[0];

        for (int i = 1; i < n; i++) {

            // Maximum sum ending at i without deletion
            keep[i] = Math.max(arr[i], keep[i - 1] + arr[i]);

            // Maximum sum ending at i with one deletion
            delete[i] = Math.max( keep[i - 1], delete[i - 1] + arr[i]);

            ans = Math.max(ans, Math.max(keep[i], delete[i]));
        }

        return ans;
    }
}
```

---

# Key Takeaways

- Extension of Kadane's Algorithm.
- Maintain two DP states:
  - `keep[]` → no deletion used.
  - `delete[]` → one deletion already used.
- At each index choose the best transition.
- Runs in **O(n)** time.
- Can be optimized to **O(1)** space.
